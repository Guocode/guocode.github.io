# Pixel Arena · 一个 MoE 模型同时玩两个无尽游戏

> 状态：**v2 无尽模式已实现并训练完成**。本文件记录最终设计、真实训练数据与踩坑过程。
> 在线页面：`/game-ai/`（GitHub Pages 静态托管）
> v1（双足赛跑 + 失控汽车，有终点）的历史设计见 git 历史。

---

## 1. 项目定位

用**一个** 22,473 参数的 MoE 策略网络，同时学会两个操作方式、状态语义、失败条件完全不同的**无尽模式**游戏：

| | Game 00 · 独轮平衡 | Game 01 · 无限公路 |
| --- | --- | --- |
| 模型 | 倒立摆躯干 + 驱动轮（**无腿**） | Frenet 坐标 + 自动巡航 |
| 前进 | 全自动：2.2 m/s 起步随时间爬升至 6.5 m/s，带步频抖动 | 全自动：巡航速度随里程爬升 8 → 26 m/s |
| 地形 | **随机起伏**：三正弦叠加伪随机函数（幅度随里程渐入），竖向加速度调制重力 + 坡度力矩 | 平路 + 解析曲率 κ(s) |
| 玩家操作 | 仅 4 档平衡力矩：前倾 / 后倾 × 软 / 硬 | 仅 4 档转向：左 / 右 × 软 / 硬 |
| 随机扰动 | OU 平衡噪声（随速度放大）+ 随机颠簸事件（半正弦冲击） | 打滑（0.7%/帧：偏航 + 漂移 + 转向力降至 45%）与爆胎（0.3%/帧：强拽 + 掉速 20%）两类事件 |
| 失败 | 俯仰超过 52° | 冲出路面 |
| 终点 | **无**——距离即分数 | **无**——里程即分数 |

两个环境都是自己写的轻量物理，Python（训练，向量化）与 JavaScript（浏览器，单实例）各实现一份，
共用同一套常量与积分公式。浏览器端永不超时，只有摔倒 / 冲出路面才结束回合。

---

## 2. 为什么能共用一个模型

* 两个游戏都是 **4 个离散动作 / 14 维观测 / 60 Hz**，接口完全对齐
* 观测语义靠 2 维任务 one-hot 区分，喂给 router 做路由依据
* 奖励都以前进距离为主项，尺度可比（advantage 仍按任务分别归一化）

---

## 3. 模型架构（MoE）

```
obs(14) + task one-hot(2)
  → shared trunk   16 → 64 → 64   (Tanh)
  → router         64 → 4         → top-2 softmax 门控
  → 4 个 expert    64 → 64        (Tanh)，按门控加权求和
  → actor(64→4) + critic(64→1)
```

* 参数量 22,473，权重 118 KB（base64 编码的 float32）
* 浏览器端**手写前向**（`assets/js/moe.js`），零依赖，首屏即用
* `train/export_onnx.py` 可导出标准 ONNX（需 `pip install onnx`，本地网络受限未生成）

---

## 4. 训练设置

* 算法：多任务 PPO（`γ=0.99, λ=0.95, clip=0.2, lr=1.5e-4, 4 epochs, mb=1024`）
* 规模：两个环境各 32 个并行实例，500 次更新，纯 CPU
* **行为克隆预热**：先用启发式策略采 3 万条示范做监督学习，再交给 PPO 微调——
  倒立摆的连续微调与车道保持靠随机探索很难起步
* Switch Transformer 负载均衡损失（系数 0.01），防止路由坍缩
* 保存综合得分最高的 checkpoint（`runner/150 + car/400`）

## 5. 结果（8 seed × 16 回合平均，训练上限 60 s，无尽模式成绩 = 失败前距离；地形 + 事件机制 v3 版）

| 策略 | 独轮平衡（起伏地形） | 无限公路（事件 v3） |
| --- | --- | --- |
| **MoE（本项目）** | **274.4 m**（跑满时限，摔倒 0%） | 500.4 m |
| 启发式规则 | 274.4 m（偶有 3% 摔倒） | 503.8 m |
| 随机动作 | 3.5 m | 10.7 m |

加入随机起伏地形后，MoE 学会贴合地形节奏的主动平衡（评估 8 seed 全部跑满时限）。
事件机制 v3（打滑改角载荷触发 + 冲量衰减 + 冷却期，爆胎概率随车速）后，
公路上简单手写规则也能逼近上限（336.9 → 503.8 m），AI 与其同档（<1% 差距）——
把随机惩罚改成可学习的行为后果，问题就变得"可解"了，这本身是个有意思的观察。
专家路由重新分化：平衡关 E3 96.5%，公路关 E2 95.3%。

### 图像输入对照实验（8 seed × 16 回合平均）

| 策略 | 观测 | 参数量 | 独轮平衡 | 无限公路 |
| --- | --- | --- | --- | --- |
| MoE（状态向量） | 14 维标量 | 22,473 | **274.4 m**（fail 0%） | **500.4 m**（fail 0%） |
| CNN + MoE（像素） | 3×40×64 RGB | 44,425 | 161.9 m（fail 78%） | 482.6 m（fail 0%） |

实现（`train/frames.py` + `train/model_img.py` + `train/train_img.py`）：
- 帧渲染：NumPy 向量化，car 透视投影 `px = PX_K/(z+PX_Z0)` + 闭式曲率积分 `_kint2`（∫κ(s+u)·u du），runner 侧视地形轮廓；R 通道 = 路面/地形，G 通道 = 中线虚线 + 车体精灵，B 通道 = 事件侧带 + 速度条；成本 0.3–0.8 ms/批（CPU 可忽略）
- 网络：conv 3→8→16→16（步幅 2）→ 640+2(任务 one-hot) → fc48 → 同款 router / 4 experts / actor / critic
- 训练：BC 预热 12000 样本 4 epochs（acc 0.44→0.67）+ PPO 300 updates，纯 CPU 27 分钟
- 结论：像素输入完全可行——公路任务约 100 updates 收敛到 480+ m（与向量版同档）；独轮平衡前 250 updates 几乎原地踏步（实时俯仰/坡度等精细标量被 40×64 低分辨率压缩），最终 fail 78%。**同样的训练预算下 14 维向量两任务稳赢：观测形式本身就是小模型最大的先验**。

## 6. v2 设计踩坑

1. **倒立摆失稳太强无法游戏** → 取 `K_INV=3.3`（e 折时间约 0.55 s）：不控制约 2 s 摔倒，
   软档力矩（±2.9 rad/s²）足以稳定，硬档（±5.8 rad/s²）用于救颠簸。
2. **平衡噪声初版太弱**，扶正一次就永远直立 → OU 过程（θ=0.8, σ=2.2）+ 随速度放大系数。
3. **颠簸事件只给常值力矩显得假** → 半正弦包络短促冲击（0.15–0.45 s，2.6 系数）。
4. **打滑不削弱转向力度**时一把方向就能救回 → 打滑期间转向执行度降到 45%，
   爆胎 60%，玩家必须提前预修正而不是事后硬拉。
5. **CarEnv 转向积分行漏写**导致方向盘完全无响应（启发式 100% 失败、比随机还差）——
   用"关闭事件 + 逐步打印 steer/psi"定位到根因后补上。
6. **启发式力矩方向接反**会让 PD 控制器变成正反馈加速摔倒——符号约定：th>0 为后仰，
   纠正后仰需要负力矩（前倾）。
7. **main.js 残留 `import { MAX_STEPS }` 而 env.js v2 已删除该导出**——ES 模块导入
   不存在的具名导出是致命 SyntaxError，整个页面脚本直接不执行（表现为"游戏无法游玩"）。
   改跨端接口时必须两端同步检查 import/export。
8. **人类模式未按键时冻结物理**（`action<0 就 return`）在 v1 迈腿游戏里无伤大雅，
   在平衡游戏里等于"暂停键"——改为未按键也 step（零力矩），站着不动会摔。
9. **地形幅度两档调参**：0.050/0.028/0.012 时 PD 启发式仍 100% 满程（太温和）；
   0.090/0.050/0.022 时启发式 3% 摔倒、偶见 205 m（有挣扎但可玩），取后者。
10. **事件 v3 重构（v2 纯随机事件被玩家投诉"被暗算"）**：打滑概率与转弯角载荷挂钩
    （猛烈过弯才甩尾，方向沿当前转向 = 行为后果），推力改冲量式线性衰减包络
    （原常值推力全程不衰，体感像"被吸附"），事件结束加 2 s 冷却杜绝连环倒霉；
    爆胎概率随车速上升（高速 hazard），事件期间巡航目标折减 25% 使掉速恢复更慢。
11. **视觉闪烁根因**：事件全屏 alpha 脉冲叠加（`0.10*sin(t)` 全屏色罩）是主源，
    加上车辆 ±3px `Math.round` 抖动、条纹屏幕锚定不滚动（ treadmill 效应）——
    改为静态侧边光带 + 方向箭头、平滑 1.6px 抖动、条纹世界锚定随里程滚动。

v1 时代的踩坑（双足腿物理：蹬地能量、被动拖离、推进上限等）见 git 历史。

## 7. 跨端一致性验证

`node tools/check_js.mjs`（开发用）：

```
JS  runner balance    mean 274.40  std 0.00  [274.40, 274.40]
JS  car lane-keeping  mean 502.74  std 9.17  [486.58, 514.63]
    (python ref:      runner 274.40±0.00 | car 508.66±8.22)
moe.js vs torch       max abs err = 2.19e-06  (OK)
```

平衡关两端完全一致（成绩由预设速度决定，与随机数无关）；汽车关因事件依赖随机数流
（Python 向量化批量预生成、JS 流式取数）无法逐位一致，取统计一致性（均值差 <1.2%）。

## 9. 复现

```bash
pip install torch numpy
python train/train_moe.py --updates 500 --lr 1.5e-4          # MoE 主训练（CPU）
python train/train_moe.py --arch mlp --updates 500           # 对照实验（可选）
python train/train_img.py --updates 300 --lr 3e-4            # 图像输入对照（可选）
python train/export_onnx.py                                 # 导出权重与页面指标
python train/record_gif.py                                 # AI vs HUMAN 回放 GIF
python train/verify.py && node tools/check_js.mjs           # 跨端一致性

# 本地预览
cd game-ai && python -m http.server 8090                     # 访问 /game-ai/
```
