02 / 成绩对比

每个游戏跑 32 回合（单回合上限 25 秒）取平均。「失败率」指摔倒 / 冲出路面的比例。

策略 机器人距离 失败率 汽车里程 失败率

启发式规则是我手写的：机器人「双腿同时着地时抬起靠后那条腿」，汽车「按横向偏移 + 前瞻曲率反打方向」。 MoE 在两个游戏上都超过了它——机器人靠更激进的前倾换取步幅，汽车则学会了提前预判弯道和失控。

03 / 专家专业化

这是整个项目最有意思的部分。我没有硬性指定「专家 0 负责机器人、专家 1 负责汽车」—— 路由是模型自己学出来的。统计每一帧的门控权重后， specialization 非常干净：

专家 机器人使用率 分布 汽车使用率 分布

机器人赛跑 90% 的权重落在 Expert 0， 汽车驾驶 99.8% 落在 Expert 1—— 两个游戏几乎完全走不同的专家，但共享同一个底层 trunk 和同一套输出头。 这正是 MoE 在多任务上的意义：用路由替代了「两个游戏各训一个模型」。

04 / 架构消融

MoE 是不是只是噱头？我训了一个参数量几乎相同的普通 MLP（20,741 vs 22,473，无专家无路由）， 用完全一样的训练流程再跑一遍。结论是：MoE 在两个游戏上都明显更好。

架构 参数量 机器人赛跑 汽车驾驶

普通 MLP 的机器人成绩从更新 50 起就卡在 68.3 m 不动了——两个任务的梯度在同一个网络里互相干扰； MoE 则持续爬到 88 m。汽车上差异更大：MLP 在 23–336 m 之间剧烈震荡，MoE 稳定跑到 544 m。

05 / 训练过程

多任务 PPO，两个环境各 32 个并行实例，共 500 次更新（约 11 分钟，纯 CPU）。 交替迈腿这类组合动作靠随机探索几乎不可能发现，所以先用启发式做行为克隆预热，再交给 PPO 微调。

汽车曲线波动很大，这是设计使然：轮子失控是随机事件，同样的策略可能跑 100 米也可能跑 500 米。 保存的是综合得分最高的 checkpoint（机器人距离 / 80 + 汽车里程 / 200）。

06 / 模型架构

小到可以直接在 JS 里手写前向：不需要 wasm 运行时，页面加载完就能玩。

为什么用 MoE

而不是两个独立模型
  • 两个游戏状态语义完全不同（关节相位 vs 车道曲率），共享 trunk 学通用表征，专家负责分化
  • 路由权重可直接可视化，模型「在想什么」不再是黑盒
  • 加新游戏时只需扩专家，不必重训整个网络

训练要点

踩过的坑
  • 交替迈腿靠随机探索发现不了 → 启发式行为克隆预热（准确率 92.8%）再 PPO
  • 两个任务奖励尺度差 6 倍 → advantage 按任务分别归一化
  • 加了 Switch Transformer 的负载均衡损失，避免路由坍缩到单个专家

为什么不用 ONNX Runtime

工程取舍
  • 模型仅 22K 参数，手写前向比拉 10 MB 的 wasm 运行时更快也更稳
  • 仓库内同时提供 train/export_onnx.py，一条命令即可导出标准 ONNX（需 pip install onnx），链路可迁到任何推理框架
  • JS 前向与 PyTorch 输出误差 1.9e-6，物理引擎两端成绩一致（机器人 78.75 m 完全相同）
  • 页面因此零依赖、离线可玩、首屏即开

07 / 两个游戏怎么设计的

两个环境都是自己写的轻量物理，Python（训练）与 JavaScript（浏览器）各实现一份，共用同一套常量和积分公式。

GAME 00 · 双足机器人赛跑

躯干刚体 + 两条弹簧腿
  • 状态：躯干位置/速度/俯仰角 + 双腿的支撑-摆动相位与落点
  • 蹬地能量：每条腿落地时充满能量，支撑期间衰减——所以站着不动会停下，必须持续换步
  • 被动拖离：腿被拉过头会自动离地，但不重置能量，主动换步才是维持速度的关键
  • 俯仰：↑↓ 设定目标倾角，由内部伺服执行。前倾步幅更大更快，但也更容易摔
  • 失败：俯仰超过 52° 或躯干触地

GAME 01 · 轮子失控的汽车

Frenet 坐标 + 随机失控扰动
  • 状态：横向偏移、航向角、车速、方向盘角，以及 4 个前瞻距离的赛道曲率
  • 赛道：曲率是解析函数 κ(s)，确定性生成，两端一致
  • 失控：每帧 1% 概率某个轮子失去抓地力，持续 0.4–1.3 秒，产生偏航 + 横向漂移
  • 观测含前瞻曲率：让策略能提前预判弯道，这是它跑赢启发式规则的主要原因
  • 失败：冲出路面，或车速降到 0.6 m/s 以下

共享接口

为什么能用一个模型
  • 两个游戏都是 4 个离散动作、14 维观测、60 Hz
  • 观测语义不同但维度一致，靠 2 维任务 one-hot 区分
  • 奖励都以前进距离为主项，尺度可比

调参记录

物理是反复改出来的
  • 早期版本机器人只会后退：弹簧的水平分力在前腿处形成无法摆脱的制动
  • 改为「弹簧只负责垂直支撑、水平完全由蹬地驱动」后才跑得动
  • 又出现速度失控到 10 m/s 被压垮 → 加上随速度衰减的推进上限

08 / 复现

纯 CPU，单台笔记本约 11 分钟训完两个游戏。

# 2. 导出 ONNX、浏览器权重与页面指标
